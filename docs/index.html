Capabilities

The Map Engine Core

The state and the math a mobile map needs, with no cloud dependencies, no API keys, and no vendor lock-in. Networking and drawing are deliberately left to the platform layer.

📦

Offline Tile Cache

In-memory LRU cache with configurable limits (256 MB default, 50K tiles). Builds XYZ URL templates and reports which tiles a region is missing, so your app can pre-fetch them.

👆

Gesture Recognition

Multi-touch state machine handling pan, pinch-zoom, rotate, and tilt. Platform-agnostic — feed it touch events, get camera deltas.

🎨

Style Engine

Structs exist. They do not parse Mapbox GL JSON (snake_case, no type / minzoom / paint stop renames). No FFI symbol reaches this module. The renderer uses a hardcoded style keyed by layer name.

🧭

Turn-by-Turn Navigation

On-device route tracking with step instructions, off-route detection (50m threshold), and arrival notification. No cloud required.

🔄

Offline Vector Editing

Local feature store with create/update/delete and sync status tracking. BBox spatial queries and GeoJSON export.

🗺️

Camera Model

Continuous zoom (0–22), bearing, pitch. Web Mercator projection with viewport-aware tile range calculation.

📍

Location Service

GPS abstraction with tracking modes (Follow, Heading, Course). Haversine distance and bearing calculations built in.

🖼️

Render Pipeline

Frame-based command buffer describing what to draw, in screen coordinates. HiDPI/Retina aware. Your platform layer executes the commands. Metal and Vulkan backends are v0.3.

Platforms

Platform Integration

Kotlin on Android. There is no Swift module, no .h, no cbindgen, no iOS CI job. The Android library fetches tiles over HTTP and draws on Canvas. The core does neither.

Android — Kotlin Kotlin 
class MapView(ctx: Context) : View(ctx) {
    private var map: Long = 0

    init {
        System.loadLibrary("terravista_ffi")
        map = tvMapCreate(
            width.toUInt(),
            height.toUInt(),
            resources.displayMetrics.density)
        tvMapSetCenter(map, 51.5074, -0.1278)
        tvMapSetZoom(map, 14.0)
        tvMapSetTileUrl(map,
            "https://tiles.tiletopia.dev/{z}/{x}/{y}.mvt")
    }

    fun destroy() { tvMapDestroy(map) }

    // JNI is hand-written, not generated from a header
    private external fun tvMapCreate(...): Long
    private external fun tvMapDestroy(s: Long)
}
Status

What Works in v0.1

The core holds map state and math. It does not talk to the network and it does not touch the GPU. The Android library fetches over HTTP and draws on Canvas. There is no iOS SDK.

Capability Status Notes
Camera, viewport, tile math ✓ Works Web Mercator, zoom, bearing, pitch, visible tile range
Gesture recognition ✓ Works Pan, pinch-zoom, rotate, tilt state machine
Tile cache ✓ Works In-memory LRU, URL template building, missing-tile queries
Offline vector store ✓ Works In-memory feature CRUD with sync status and GeoJSON export
Style parsing Unreachable Snake_case structs, no Mapbox GL JSON parse. No tv_ FFI symbol. Renderer uses a hardcoded style.
Turn-by-turn navigation ✓ Works Tracks progress along a route computed elsewhere
C FFI ✓ Works Map lifecycle, camera, gestures, cache
HTTP tile fetching ✓ Android library The core has no HTTP client. The Android library fetches over HTTP.
MVT decoding ✓ Works Layers, features, geometry and attributes, placed as screen-space draw commands
Metal rendering (iOS) Roadmap v0.3 The renderer emits draw commands, it does not execute them
Vulkan rendering (Android) Roadmap v0.3 Same, the platform layer owns the GPU
Route computation Out of scope Use Itinera or another routing engine

Quick Start

Get Started in Minutes

Clone, build, and integrate into your mobile app.

Terminal bash 
# Clone
git clone git@github.com:GeoLang/terravista.git
cd terravista

# Build & test
cargo build
cargo test

# There is no iOS binding. Cross-compiling the C ABI for aarch64-apple-ios
# does not produce a Swift module.

# Build for Android
rustup target add aarch64-linux-android
cargo build --target aarch64-linux-android -p terravista-ffi --release
