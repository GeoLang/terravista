Capabilities

The Rust Core

The map state and the math a mobile map needs. The core makes no network calls and needs no API key. The Android library does the fetching and the drawing.

Offline Tile Cache

In-memory LRU cache with a size cap and a tile count cap (256 MB and 50,000 tiles by default). Builds XYZ URLs and reports which tiles a region is missing, so your app can pre-fetch them. A region counts, estimates and lists its tiles. In the Rust API only, a set of tiles serializes to a TVPK archive.

Gesture Recognition

Multi-touch state machine with three states: idle, pan, and a two-finger pinch that zooms and rotates together. No gesture sets pitch. Feed it touch points from any platform and it moves the camera.

Vector Tiles

MVT decoding by jung-mvt, straight to screen-space points, lines and polygons with holes. Each layer name gets a fixed look, and one call overrides a layer's fill, stroke and width. There is no style spec and no labels.

Turn-by-Turn Navigation

Tracks progress along a route computed elsewhere: step instructions, distance to the next step and to the end, off-route past 50 m, and arrival.

Offline Vector Editing

In-memory feature store with create, update and delete, and a sync status per feature. Bounding-box queries and GeoJSON export. Rust API only, no FFI function reaches it.

Camera Model

Continuous zoom from 0 to 22, bearing and pitch. Web Mercator projection, visible bounds and tile range for the viewport.

Location Service

The host feeds location fixes in, and the camera follows them in Follow, Heading or Course mode. Haversine distance and bearing.

Render Pipeline

A frame command buffer describing what to draw, in device pixels. The platform layer draws it, as the Android library does on Canvas. No GPU backend is built.

Design

Layered Architecture

Kotlin calls a hand-written JNI library, which calls the C ABI, which wraps the Rust core.

Platforms

Platform Integration

Android only. There is no Swift module and no generated C header. An app takes com.github.GeoLang:terravista from JitPack and puts MapView in a layout. It gets raster and vector tiles, a disk cache read before the network, offline regions that are never evicted, a user location dot and route progress. The Android README covers the full API.

Android: Kotlin Kotlin 
// app/build.gradle.kts, with https://jitpack.io in the repositories
implementation("com.github.GeoLang:terravista:0.4.0")

// an Activity whose layout holds a dev.geolang.terravista.MapView
val map = findViewById<MapView>(R.id.map)
map.setCenter(51.5074, -0.1278)
map.zoom = 14.0
map.vectorTileUrlTemplate =
    "https://tiles.example.com/{z}/{x}/{y}.mvt"

// in onDestroy, frees the native map
map.destroy()
Status

What Works in v0.4

The core holds map state and math. It does not talk to the network and it does not touch the GPU. The Android library fetches over HTTP and draws on Canvas. There is no iOS SDK.

Capability Status Notes
Camera, viewport, tile math ✓ Works Web Mercator, zoom, bearing, pitch, visible tile range
Gesture recognition ✓ Works Pan, and a two-finger pinch that zooms and rotates, with a 5 degree dead zone before rotation starts
Tile cache ✓ Works In-memory LRU, URL template building, missing-tile queries
Offline vector store ✓ Works In-memory feature CRUD with sync status and GeoJSON export. Rust API only
Offline regions and tile packages ✓ Works Tile count, size estimate and enumeration for a bounding box. The Android library downloads and stores regions. The TVPK archive is Rust API only
Style spec Planned Not built. Style structs exist in the core, but nothing reads them and no tv_ function reaches them. Each layer name gets a fixed look, overridable per layer

HTTP tile fetching ✓ Android library The core has no HTTP client. The Android library fetches over HTTP and caches tiles on disk
MVT decoding ✓ Works Layers, features, geometry and attributes, placed as screen-space draw commands
iOS binding and Metal rendering Planned Not built. There is no iOS or macOS code
Vulkan rendering (Android) Planned Not built. The Android library draws on Canvas
Route computation Out of scope Use Itinera or another routing engine

Quick Start

Build from Source

Build and test the Rust workspace, then cross-compile the C ABI for Android. The Gradle build is in the Android README.

Terminal bash 
# Clone
git clone https://github.com/GeoLang/terravista.git
cd terravista

# Build and test
cargo build
cargo test --all

# Build the C ABI for Android, needs ANDROID_NDK_HOME and a linker config
rustup target add aarch64-linux-android
cargo build --target aarch64-linux-android -p terravista-ffi --release
